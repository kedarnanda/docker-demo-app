# node_modules — Everything You Need to Know

---

## What is node_modules?

`node_modules` is a folder where npm stores all downloaded packages that your app needs to run.

```
my-project/
├── server.js
├── package.json
└── node_modules/          ← created by npm
      ├── express/         ← web server package
      ├── mongodb/         ← mongodb driver package
      ├── body-parser/     ← request reader package
      └── 500+ more...
```

---

## How is node_modules created?

`node_modules` is created when you run `npm install` — **not** when you run `node server.js`.

### Correct order:
```bash
1. npm install        ← creates node_modules
        ↓
2. node server.js     ← uses node_modules to run
```

### What happens step by step:
```
You run: npm install
        ↓
npm reads package.json dependencies:
  "express": "^4.22.2"
  "mongodb": "^3.7.4"
  "body-parser": "^1.20.6"
        ↓
npm downloads all packages
        ↓
saves them into node_modules/ folder
        ↓
records exact versions in package-lock.json
```

### If you skip npm install:
```bash
node server.js
# Error: Cannot find module 'express'   ❌
# Error: Cannot find module 'mongodb'   ❌
```

---

## Who uses node_modules?

Your `server.js` uses the packages via `require()`:

```javascript
let express     = require('express')      // uses express from node_modules
let MongoClient = require('mongodb')      // uses mongodb from node_modules
let bodyParser  = require('body-parser')  // uses body-parser from node_modules
```

`require()` tells Node.js to go into `node_modules` and load that package.

## Why NOT to push node_modules to GitHub?

### Reason 1: It is huge
```
node_modules/    ← can be 100MB - 500MB in size!
```
Nobody wants to upload or download hundreds of MBs unnecessarily.

### Reason 2: It can be recreated instantly
Anyone who clones your repo just runs:
```bash
npm install
```
npm reads `package.json` and downloads everything automatically. No need to store it!

### Reason 3: It is not your code
```
Your code      → server.js, index.html   ✅ push this
node_modules   → downloaded from npm     ❌ not your code
```
GitHub is for YOUR code, not downloaded packages.

### Reason 4: It causes conflicts
Different operating systems generate slightly different node_modules:
```
Mac     → node_modules (mac version)
Windows → node_modules (windows version)
Linux   → node_modules (linux version)
```
Pushing one version breaks it for others on different OS!

---

## Simple analogy

```
package.json   =  recipe card
node_modules   =  ingredients

You share the RECIPE not the ingredients!
Everyone buys their own ingredients (npm install)
```

## How to ignore node_modules — .gitignore

Create a `.gitignore` file in your project:
```bash
echo "node_modules" > .gitignore
```

Git will completely ignore the `node_modules` folder — it will never be tracked or pushed.

```
# .gitignore
node_modules/     ← git ignores this completely
```

## How node_modules works in Docker

Since we don't copy `node_modules` into Docker, the Dockerfile recreates it:

```dockerfile
COPY package.json .        # copy the recipe (package.json)
RUN npm install            # recreate node_modules inside container
COPY . .                   # copy your code (no node_modules!)
CMD ["node", "server.js"]  # run the app
```

### Visual:
```
Your laptop                      Docker container
│                                │
├── server.js       COPY ───────►├── server.js
├── package.json    COPY ───────►├── package.json
│                                │        ↓
├── node_modules                 │   RUN npm install
│   (NOT copied!) ❌             │        ↓
│   too big!                     │   node_modules/ ← created fresh inside!
```

## Summary — Files to push vs not push

| File | Push to GitHub | Copy in Dockerfile |
|---|---|---|
| `server.js` | ✅ Yes | ✅ Yes |
| `package.json` | ✅ Yes | ✅ Yes |
| `package-lock.json` | ✅ Yes | ✅ Yes |
| `.gitignore` | ✅ Yes | ❌ No |
| `node_modules/` | ❌ No | ❌ No — npm install creates it |

## Key rule to remember

```
npm install    →  CREATES node_modules
node server.js →  USES node_modules

Always run npm install before node server.js!
```
